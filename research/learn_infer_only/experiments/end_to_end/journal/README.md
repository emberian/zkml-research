# Executable BFV journal and selected release

[DERIVED scope] This is benchmark **R**: a separately trusted full-key reader, an honest validating authority, a trusted plaintext issuer and a trusted query authorizer. It is not NoMasterRead, distributed custody tier C, a production deployment, a succinct proof, or an OS isolation result. Ed25519 role authentication is classical. Authority signing-key compromise is an indirect read capability in this baseline: a valid signature can falsely label a ciphertext as a selected query result. The companion `controls.py` deliberately tests that premise failure. The parent-owned verified-reader successor is separate.

[SOURCE] Actual BFV arithmetic is the sibling `../crypto/src/main.rs` CLI: fresh public-key encryption; per-route accumulator `acc + fresh - exact_original_old`; signed public-query polynomial multiplication; trusted coefficient-576 decryption. Fixed parameters are N4096, two Q83 limbs, plaintext modulus4294828033, width577, W32, two public routes. The fixed crypto `program_id` and full parameter descriptor are copied into genesis. Ciphertext key IDs are declared metadata, not a proof of honest key provenance. Signed issuer range/feature assertions remain premises about an honest issuer.

[DERIVED implementation] Trusted setup makes OS-random BFV keys and separate Ed25519 issuer, command-authorizer and authority keys. Each private role config pins the genesis digest. Genesis pins the full public-key file hash, BFV key ID, fixed params/program, exact journal source hashes, authority/issuer/authorizer verification keys, recipient and query policy. The issuer checks its configured public-key bytes before encryption. The reader pins its secret-key bytes and the genesis key relation. These are local trusted-config boundaries, not remote attestation.

[DERIVED implementation] A signed action binds genesis, params/program/version, key ID/full public-key hash, kind, route, request ID, nonce, parent global revision and canonical state digest, recipient, and either fresh ciphertext/record/feature/range assertions or selected query bytes. Query vectors must match a preregistered `(query digest, route)` policy and carry a fresh contextual command-authorizer signature. Authorization of coordinate queries remains a disclosure capability; signatures do not prevent permitted-interface inference.

[DERIVED implementation] The host proposes result ciphertext, exact expired-ciphertext identity and next-state digest. The authority independently loads its own immutable CAS, rehashes complete ciphertext bytes on every trusted load, checks strict canonical BFV representation/params/key metadata, and calls the actual CLI to recompute Learn or Infer. Canonical inspection is cached only by complete byte digest; bytes are still rehashed. It compares the proposed result against the recomputed result. No caller filesystem path is an authority input. CAS writes are fsynced before a SQLite WAL/FULL transaction commits.

[DERIVED implementation] The current state is a canonical manifest of route queues, accumulators and per-route admission counts. Its digest commits through SHA256 references to complete canonical ciphertext bytes and to genesis/params. A global revision advances on **both** Learn and Infer. Only Learn advances that route's admission count. Each journal entry stores the signed request and a small delta referencing immutable ciphertexts; it does not copy the full W-entry queue. Full public replay checks signatures, sequential parents, unique request/nonce/input identities, applies deltas and can independently recompute every ciphertext operation.

[DERIVED implementation] `BEGIN IMMEDIATE` serializes exact retry lookup, currentness, nonce/input uniqueness, recomputation and journal/state installation. An exact historical request returns its stored envelope even after newer revisions. A changed request with the same ID is refused. Infer publication happens after the committed row exists; recipient acknowledgment is recorded separately. Retry may publish repeatedly, while the reader's private transaction log records one logical packet per selected nonce. This does not prove physical exactly-once delivery, storage hardware durability or honest persistence of the authority file.

[DERIVED implementation] The reader only accepts authority-signed **Infer** envelopes matching an independently registered signed query ticket, fixed recipient, exact output hash/params/key and the finalized context. A Learn envelope is refused even though it is genuinely authority-signed. Reader plaintext output is kept in an ignored private SQLite log; normal reader RPC returns only acknowledgment. The baseline reader trusts the authority's public recomputation. Rolling back the independent authority database deliberately violates the continuity premise and can create two different signed actual successors from one parent.

[EXECUTED preliminary] `results/smoke_001/report.json` records two Learn and two Infer events, distinct fresh ciphertexts, two private-oracle agreements, an exact old retry after newer events, and full recomputed replay. `results/private_001/report.json` records40 OS-random issuer-only observations, eight actual expiries and four private comparisons, all matching. These initial runs precede the exact JSON-number alias repair identified by independent review; they are retained as versioned evidence, not the final hardened run.

[EXECUTED review finding] Independent critic preserved an accepted Boolean/float alias witness against the initial source: Python equality allowed `program_version=True`/`1.0` or float-valued range bounds to compare equal to the originally signed integer action. The numerical operation was unchanged, but exact signed-context encoding was not preserved. Repair and regression status will be recorded with final run hashes. Initial control evidence also preserves a post-publication crash-injection race: requesting SIGKILL could briefly return before delivery, allowing an RPC reply. The test hook must wait after requesting termination; this is a fixture boundary, not a normal client-selectable mode.
