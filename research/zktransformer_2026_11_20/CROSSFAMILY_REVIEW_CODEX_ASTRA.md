## 1. Lookup identities and claim binding

**[DERIVED] Range folding is consistent between prover and verifier.** Let \(A_{ij}(x,t)\) be the selector for node \(i\), block \(j\), let \(u_i\) be its input claim point, and set \(w_{ij}=\beta^i\gamma^j\). For each group of equal table width, the checked identity is
\[
\sum_t (T(t)+\alpha)\sum_{ij}w_{ij}A_{ij}(u_i,t)
=\sum_{ij}w_{ij}(m_{ij}+\alpha).
\]
The constant coefficient checks the weighted table values. The coefficient of \(\alpha\) checks row mass one. The prover absorbs every middle claim before drawing the folding challenges. The verifier independently recomposes each node’s value from its block digits and checks the terminal product at the sumcheck point. Grouping by `table_vars` is sufficient even when input arities differ, because each input point is already bound. The last partial block uses its actual width. `src/dag/mod.rs:641`, `:1397`, `:1439`, `:1450`, `:1463`, `:1486`, `:1590`, `:1626`, `:1645`; `src/util/poly.rs:1328`.

**[DERIVED] Booleanity uses a different grouping for a mathematical reason.** Its summand is
\[
\operatorname{eq}(s,z)\sum_{ij}w_{ij}^{\,2}A_{ij}(z)(A_{ij}(z)-1).
\]
Here the whole selector is unbound, so equal **total** arity is required. The sparse prover uses actual entry values, pairs even and odd indices, treats missing siblings as zero, and folds the same LSB-first coordinate as the dense equality polynomial. The degree is at most three. Squaring each weight agrees on both sides and introduces no cross terms. The equality array still occupies \(2^{\text{aux\_num\_var}}\) field elements. `src/dag/mod.rs:1505`, `:1527`, `:1672`; `src/crypto/sumcheck/linear_prover.rs:512`, `:522`, `:565`, `:590`, `:634`.

**[DERIVED / EXECUTED] TwoPow is the same table check with one block and weights \(\beta^i\).** Its table is \(2^{15-t}\). The structured MLEs are \(\sum_j2^jr_j\) for range and \(\prod_{j=0}^3(2^{2^j}(1-r_j)+r_j)\) for TwoPow. Both agreed with independent dense interpolation at **64/64 off-cube BabyBear points**. Selector storage is `input_index + (table_index << d)`, so the opening point is `input_point || table_point`. Lookup claims now enter the opening queue before PCS proofs are made, and verification compares edge, block, point, and extracted value. `src/util/poly.rs:1043`, `:1370`, `:1393`; `src/dag/mod.rs:872`, `:1233`, `:1267`, `:1745`, `:1786`, `:1882`, `:1913`.

Two preconditions matter. Boolean entries plus row mass one imply one-hotness when the row width is below the field characteristic, as it is for the four-bit BN254 table. Also, TwoPow’s Booleanity exemption checks only whether the input’s **producer** appears in `self.range`. The normal builder supplies the right selector, but the generic DAG interface should validate the specific edge, block and width. A split width below four also conflicts with the prover’s one-block assertion. `src/dag/builder.rs:346`, `:389`; `src/dag/mod.rs:549`, `:1804`, `:1873`.

| **High · Softmax and sigmoid advice lacks its defining constraint** | `SoftmaxConst::run` repeats one log-sum-exp shift per row, but its witness has the full score shape and its verifier returns `true`. Both attention builders add it elementwise and exponentiate. The paper requires a common row shift **and** an approximately unit row sum. Committing \(y\) alone does not supply it. ScaleUp computes exactly \(y=Rx\), yet for \(R>1\) verifies a whole interval for \(Rx-y+\lfloor R/2\rfloor\). Exact upscaling needs only a linear equality. ## 3. Tensor layout, paper correspondence and PPL

- **[DERIVED] Layout is internally consistent for supported contractions.** Axis zero has stride one. Add/Sub right-align broadcast axes, then take their coordinate blocks in increasing axis order. Broadcasting can fill padded cells, so a later logical reduction needs a mask. The new one-shot mask correctly removes padded sequence and vocabulary cells before the argmax comparison. The inequalities establish membership in the set of maximizers, allowing ties. `src/dag/mod.rs:90–115`; `src/util/shape.rs:139–152`; `src/basicblock/add.rs:11–28`, `:115–127`; `src/dag/oneshot.rs:96–114`.
- **[DERIVED] ChangeShape is a padded-buffer reinterpretation.** It preserves the polynomial, point and evaluation. Equal padded arity does not imply that a logical flatten preserves element positions. For example, `[3,3]` and `[9]` both occupy 16 cells, but the former has padding inside its logical traversal. Permute’s wiring polynomial uses the correct padded strides for unique output destinations. Repeated destinations give overwrite semantics in `run` and addition in the proof. Reducer correctly checks the weighted equality polynomial and binds the reduced point for multiple claims about the same edge. `src/basicblock/shape.rs:13–17`, `:44–50`; `src/basicblock/permute.rs:15`, `:39`, `:119–129`; `src/basicblock/reducer.rs:70–77`, `:87–110`.
- **[DERIVED] The new ExpHelper remainder bounds are correct for its nonpositive input domain.** For \(L=\operatorname{round}(2^s\ln2)\), the two checks select exactly \(L\) consecutive integers, from \(-\lfloor(L-1)/2\rfloor\) through \(\lfloor L/2\rfloor\), assuming the small-range sums cannot wrap. This agrees with the witness tie rule. The Q15 builder clamps at \(-14L\), giving a tail value of **2 Q15 units**, including sufficiently negative masked scores unless separately zeroed. The paper describes a cubic and discusses clamping near \(k=15\). The note’s description of a degree-five Taylor polynomial on a one-sided interval needs correction. `src/basicblock/exp.rs:33–55`; `src/dag/builder.rs:127–131`, `:357–381`, `:421–432`; `zkTransformer.txt:468`, `:509–515`, `:532–539`; `SEAM_AND_PRIOR_ART.md:129`.
- **[REFUTED: Appendix F Algorithm 1 implemented for unequal residual arities]** Rust broadcasts only the equality table. Each operand retains its own residual arity, the linear prover asserts every array has the full union size, and claim construction appends every round challenge to every operand. The paper explicitly projects away absent variables. Unequal original ranks can work when fixing the degree-one free indices leaves identical residual coordinates, as in native GQA. The paper’s `bsdhv,btdh->bsth` with nontrivial `v` falls outside that case. `zkTransformer.txt:1133`, `:1214–1227`; `src/basicblock/einsum.rs:539–553`, `:559–565`, `:620–626`; `src/crypto/sumcheck/linear_prover.rs:49–52`.

The branch therefore supplies no implementation evidence for zero knowledge. There is also a separate Fiat–Shamir qualification: Merlin emits 64 bytes, but the Arkworks conversion truncates to one modulus-width buffer before reduction. The Lean uniform-field probability does not transfer exactly to that sampler. `zkTransformer.txt:1107–1128`, `:1152–1162`; `src/crypto/polycommit/kzh3.rs:109–124`, `:660–666`; `src/crypto/sumcheck/linear_prover.rs:59–74`; `src/util/transcript.rs:38–41`; `src/util/poly.rs:72–77`.

## 4. Lean and Lemma 3.2

**[DERIVED] The two-operand theorem has the right scope.** The theory file covers the canonical contraction and explicit zero padding. The assurance file binds free-once indices, retains shared free indices under `eq`, and proves projection across unused coordinates. Its wrong-output-table error bound is
\[
\frac{\mu_L+\mu_R+\mu_S+3(\mu_S+\kappa)}{|F|}
\]
for uniform challenges and a prefix-respecting, degree-bounded prover. The equivalence with the terminal verifier assumes authentic openings `hZ`, `hA`, `hB`. It establishes an algebraic predicate, leaving PCS binding, Fiat–Shamir, Rust correspondence and knowledge extraction as separate obligations. The characteristic-free identity also survives fields where Rust’s integer interpolation grid is unsuitable. `formal/Theory/ZkmlEinsum.lean:119`, `:159`, `:328`; `formal/Assurance/ZkmlEinSumcheck.lean:121`, `:354`, `:626`, `:734`, `:772–785`, `:825–835`.

**[REFUTED: justification for “two soundness bugs” in the note]** The paper really does use maximum operand arity \(v\) where its round-count argument needs the union of summed coordinates. The Lean `bp,bq->b` example establishes five rounds and \(v=3\). But \(15/|F|>9/|F|\) compares **two upper bounds**. It supplies no lower bound on acceptance. With verifier-enforced incidence degrees, that example has inner degree sum \(3+1+1+1+1=7\). Likewise, the outer Schwartz–Zippel term belongs to the wrong-*table* game; the paper’s proof discusses the inner evaluation claim. With no inner rounds, the paper’s \(v\) can still be positive. The Lean forged table over \(\mathbb F_7\) has outer collision probability \(1-(6/7)^3=127/343\). Its acceptance at a fixed colliding outer point demonstrates the event, without disproving the published numerical inequality. I would retain the repaired theorem and change the verdict to “invalid round-count argument and distinct outer-table game.” `zkTransformer.txt:369–387`; `FORMAL_EINSUMCHECK.md:28–33`; `formal/Assurance/ZkmlEinSumcheck.lean:900–904`, `:921–938`, `:946–953`.
