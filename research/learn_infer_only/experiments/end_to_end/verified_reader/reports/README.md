# Executed verified-reader driver

[EXECUTED, 2026-09-07] `run_004/report.json` is the final complete run. The driver
used real serialized BFV objects, a new OS-random key setup and forty new private
577-coordinate inputs. Its main admitted history is forty Learn operations and
four Infer operations, with eight exact-original expiries and final revision 44.
The verifier independently reached the authority's exact state and ordered
journal. Eight private scalar comparisons passed: four for the baseline reader
and four for the verifying reader. No private scalar is recorded here.

[EXECUTED] The test exercised 23 refusals, each paired with an actual before/after
verified-head check. They include second-before-first delivery; a verified Learn
presented for release; a valid authority signature over a substituted output;
receive before verification; a verified Infer without its independent ticket;
wrong-original expiry using an actual alternate BFV computation; wrong expiry
delta; recipient/query/ciphertext substitutions; boolean/float aliases; duplicate
JSON keys and NaN; and an alternate branch finalized by a real authority process
started from a copied genesis database. The retained verifier refused the latter
at `verifiedStaleParent` while preserving revision 44.

[EXECUTED] The substituted output was a fixed public scalar 8128, generated by
encrypting a public 127 at coefficient 576 and performing six public doublings.
It is independent of private test outcomes. The selected first query's actual
score has magnitude at most 1270. An isolated baseline reader with the legitimate
query ticket accepted this valid-signature wrong ciphertext; its private result
equaled 8128. The verifier refused the same envelope at
`verifiedArithmeticProposal`, then refused release at `unverifiedFinalization`.
The honest envelope subsequently passed. This is an arithmetic-substitution
falsifier; Faraday's separately owned `journal/signer_route_control.py` supplies
the stronger actual-unselected-coordinate extraction control.

[EXECUTED] Historical sync and receive retries passed before and after an actual
reader SIGKILL and process restart. Its head and four logical delivery records
survived. It made exactly four scalar-decryption calls including retries. These
tests kill after successful calls return; they do not enumerate every possible
instruction-level crash interleaving.

[EXECUTED] The final run took 42.171083292 seconds on this shared machine. All
costs, including control work, are in `run_004/report.json`; JSONL evidence keeps
actual commands and elapsed times. The verifier executed 42 Learn computations
(40 admitted plus two failed-expiry recomputations), five Infer computations
(four admitted plus the substituted-output attempt), 86 inspections and four
decryptions. Median subprocess wall times were 24.367292 ms for Learn,
32.340750 ms for Infer and 20.459708 ms for decrypt. These include process launch,
parameter setup, file decoding and serialization; they are not arithmetic-only
or deployment benchmarks.

[EXECUTED] Each wrapped ciphertext is 85,103 bytes. This one-route workload ends
with 32 queued ciphertexts and two accumulators, totaling 2,893,502 logical live
ciphertext bytes. The verifier CAS retains 87 files totaling 7,236,330 bytes,
including query objects and historical/recomputed artifacts. All verifier and
baseline-control RPC traffic totals 6,472,768 request bytes and 23,420 response
bytes. Host/authority/reader command costs and RPC costs are separated by role
and process instance in the report. Only fresh input, public query and initial
zero blobs were uploaded to the verifier: it created every result by public
recomputation. The extra copied-authority branch re-encrypted one retained
private input; its Learn was not installed in the main history.

[SOURCE] The Rust build and dependency provenance is in the adjacent
`crypto/README.md`, `crypto/validation.json` and `crypto/artifact_hashes.json`.
Python3 and `cryptography` 50.0.1 were used here. Each new execution uses fresh OS
randomness; ciphertext bytes and timings are not expected to reproduce exactly.
There is no seeded oracle key setup in this driver and no model rerun.

[DERIVED scope] This is benchmark R with a full-key trusted reader. It narrows
the authority's arithmetic trust requirement. It does not remove the reader's
ability to decrypt all state, establish OS isolation, prove source/range/key
provenance, make the allowed query policy private, establish availability or
claim end-to-end post-quantum security. Issuer and command authorization remain
trusted, reader persistence must resist rollback and the authority can stall.
