## Conjunctions the evidence does not support

[DERIVED] Combining “BFV utility passed,” “a different constructor creates no
master,” and “a different fixed-coordinate scheme has a QPT reduction” does not
give their conjunction. The learning laws, message images, surviving credentials
and security games differ. In particular, putting the existing four-bin encoder
into a 577-coordinate fixed-span scheme would not create private useful state:
the existing exact-score span determines its effective aggregate and queue.

[DERIVED] A journal can refuse an unauthorized envelope while a surviving key
reads the ciphertext directly. Deferred decoding demonstrates phase order, not
key absence; a full key loaded by a verifier counts even if no decrypt call occurs.
Erasing a dealer master is also insufficient when known initialization plus the
exposed issuer history reconstructs state. Private ingress and the issuer
corruption/knowledge contract belong in the same claim.

[DERIVED] Universal Lean arithmetic does not identify compiled Rust/TFHE behavior;
finite replay does not prove universal byte determinism. A low statistical error
plus heuristic lattice cost does not certify a whole PQ implementation. The new
LWE/RLWE constructions therefore do not close the existing BFV-parameter concern
in VERDICTS §7.8 or the receipt's separate quantum-oracle/composition obligations.

## Smallest decisive next theorem

[DERIVED recommendation] Prioritize **one complete-view restricted-release lemma
for a fixed emitted EMA Infer after a two-Learn prefix**, rather than another
full-key throughput demonstration. Reuse the established Lean arithmetic model;
the new content is the release capability and its joint view. This is a proposed
theorem contract, not authorization to run an experiment or a claim that an
existing primitive already supplies it.

[DERIVED required statement] Specify one concrete setup/credential algorithm and
an internal release guard bound to genesis, exact source/descriptor, parent state,
authorized input chain, query, recipient and consumed slot. Under an explicit
continuity assumption, expose the union of all permitted surviving keys, copies,
evaluation material, archives and issuer knowledge. Prove that its real view
reveals only the declared authorized sign and leakage while returning reusable
encrypted state. No raw FHE key may become an exposed “one-use” payload.

[DERIVED decisive witness] The same contract must exhibit distinct **reachable
learned** states or history distributions with a meaningful protected predicate,
equal exposed issuer views and equal observations under every allowed bounded
continuation/fork. The histories must exercise the actual learning law and a
useful output; an unused padding bit or ambient nullspace alone is insufficient.
If that witness fails on the existing feature image/interface, retain the scoped
failure and revise that contract before cryptographic integration.

[SOURCE / DERIVED feasibility gate] The existing
[capsule review](../receipt_key_capsule/REPORT.md) pinpoints why the proposed
lemma is decisive: generic MIFE requires compatibility at every accepted public
slot replacement, and the surrounding HE package requires a joint auxiliary-view
argument. Fixed-capability witness encryption does not construct a reusable
restricted decryptor. An accepted signature being hard to find does not remove
it from a universal compatibility premise. Closing that exact joint lemma would
connect dimensions two and three for the same nonlinear computation; failure
would prevent another unsupported end-to-end claim. PQ lifting and concrete
runtime refinement would remain explicitly subsequent obligations.
