[DERIVED: intended scoped composition] Honest initialization privately delivers
only each fixed projection scalar to a separate recipient registration process.
Each process chooses its dedicated scalar. Public transformation tokens then
convert a fixed projection of encrypted state into a two-element ciphertext for
that recipient. The initializer never serializes the full master vector; deletion
of temporary delivery files and process exit do not prove physical erasure.

[DERIVED] The public journal retains the exact original input ciphertext needed
for each window expiry. Issuer and command signatures bind the encrypted input or
fixed query to genesis, parent and route. Inference additionally binds context,
row, row digest, token digest and recipient. The authority recomputes; then the
recipient verification service independently recomputes the whole history and
checks the signed transition before durably accepting the output ciphertext.
Its public ACK means **verified ciphertext accepted**, and performs no scalar
decoding. That service config contains no recipient key paths. A separate private
`drain.py` opens accepted outputs afterward, using the row's dedicated scalar and
private dedup database. Public events and cost logs omit scalar values, scalar
hashes, private decoding calls and private decoding durations.

[DERIVED: trust boundary] The private drain holds all 16 dedicated recipient keys,
so it is the full fixed-span recipient coalition. It can recover every fixed-span
projection on retained individual inputs and snapshots, independently of the
honest journal's selected requests. The software dedup counter is not a capability
restriction on that coalition. Host confidentiality assumes no recipient output
or side-channel feedback beyond this public protocol. This shared-account run is
role/process separation, not OS isolation. Physical timing, storage/erasure,
initializer/issuer side channels and arbitrary malicious-recipient feedback are
excluded. Classical DDH, Ed25519 authentication and SHA-256 content addressing
are separate assumptions; no post-quantum, general neural confidentiality,
nonlinear output policy, private recipient self-restraint, or hardware-rooted
finality claim is made.

[DERIVED: context validation reuse] Setup first fully validates the canonical
public context's subgroup membership and all 16 token equations. Genesis/config
pin its digest, the validation record, all four crypto runtime sources and the

context's schema/ranges/identities, and skips only those already validated public
algebra checks when the pinned digest matches. Ciphertext subgroup checks remain
active on every actual CLI load. The digest reuse is an explicit trusted setup
cache, not a cryptographic certificate of correct setup or erasure.
