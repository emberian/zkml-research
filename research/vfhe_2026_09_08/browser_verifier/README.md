# Standalone vFHE proof verifier

[SOURCE] This is a thin WebAssembly wrapper around the existing DescriptorIR-v2
Plonky3 verifier, using the **shared**
`vfhe_public_preprocessing_backend::FixedPublicPreprocessing` adapter from
`../proved_operation/backend`. It uses the same postcard proof and typed
DescriptorIR-v2 statement as the native prover. It adds no arithmetic AIR,
prover or FHE evaluator and contains no independent configuration copy.

[SOURCE] The adjusted backend ID ends in
`|public-preprocessing-xoshiro256pp-0.8.1-v1`. Only public preprocessing commitments
use the adapter's deterministic public salts; the adapter forwards the other
PCS operations to the existing hiding implementation. This identifies a
different configuration from the original reference backend. No stronger
security claim follows from the wrapper or the finite checks.

[EXECUTED] **Two genuine proofs pass through the same JS/WASM consumer.**
Changing public row zero's first output digit makes each proof fail in the
actual verifier. The generated module is 2,063,586 bytes, SHA256
`96137c1ed0ad5fc7584ca72ef006ff70ac1951831408ee12ab22ce3879f6f908`.
The native CLI also builds against the same shared adapter.

| Public fixture | Actual accepted statement | Proof bytes | Accept / changed-output reject |
| --- | --- | ---: | ---: |
| `fixtures/operation/` | BFV ciphertext `3·A + 5·B`, 8,192 × 64 public coefficient rows | 557,834 | 1,669 / 1,608 ms |
| `fixtures/learner-expiry/` | Real learner event 65 `acc + fresh − old`, 8,192 × 57 exact serialized NTT-slot rows | 508,777 | 1,747 / 1,695 ms |

[EXECUTED] Timings are the retained single runs in Node's WebAssembly runtime,
using the same generated module and JS API supplied for browser integration.
They are not browser-engine benchmarks. Commands/results are
`node web/verify-fixture.mjs fixtures/operation` → `results/verify-wasm.json`
and the same command with `fixtures/learner-expiry` →
`results/verify-wasm-expiry.json`. Both exited zero with empty stderr; no proof
was generated by this consumer. `BROWSER_PACKAGE.json` freezes the static assets
and fixtures for root's microsite integration.

## Browser API

Serve `web/` as static files; preserve its `pkg/` directory. No server-side
verification is involved. The JS module works in a browser or Web Worker.

```js
import { createVerifier } from './verifier.js';
const verifier = await createVerifier();
const result = verifier.verify({
  template,                   // exact descriptor JSON text
  publicRows,                 // number[][] or JSON text; canonical BabyBear words
  proof,                      // Uint8Array containing the postcard proof
  expectedTemplateSha256,     // lowercase SHA256 from approved application config
});
if (result.verified) {
  // The real existing STARK verifier accepted this selected public statement.
}
```

[SOURCE] `verify` returns `{verified, backend, public_rows, public_width,
proof_bytes, template_sha256, error}`. It replaces only exact-public table 11,
requires zero separate scalar public inputs, rejects noncanonical/ragged rows,
checks the template transport pin and rejects trailing proof bytes. The actual
proof decision comes from the shared `FixedPublicPreprocessing::verify`, which
uses the existing generic IR2 verification routine.

[SOURCE] The application chooses both its approved template pin and the public
rows it wants checked. Do not trust a template/hash pair supplied by an unknown
prover: that would let the prover choose the claim. The hash authenticates exact
template transport bytes; it is not the proof protocol's semantic identity.
The underlying verifier binds the parsed relation and exact public rows.

[SOURCE] Verification is synchronous and may take time. Use `web/worker.js`
to keep the page responsive:

```js
const worker = new Worker('./worker.js', { type: 'module' });
worker.onmessage = ({ data: { id, result, elapsedMs } }) => { /* render result */ };
worker.postMessage({ id: 'operation-1', request: {
  template, publicRows, proof, expectedTemplateSha256,
} });
```

## Build and standalone usage

[SOURCE] Local prerequisites are the pinned Rust dependencies in `Cargo.lock`,
the `wasm32-unknown-unknown` target and `wasm-bindgen 0.2.127`. Companion sources
are read-only path dependencies; build outputs stay in this directory.

```sh
sh build.sh
node web/verify-fixture.mjs fixtures/operation
node web/verify-fixture.mjs fixtures/learner-expiry
```

[SOURCE] To check caller-selected files directly without a fixture runner:

```sh
node web/verify-file.mjs template.json public_rows.json proof.bin EXPECTED_TEMPLATE_SHA256
```

[SOURCE] This calls WASM directly in Node and exits 0 for acceptance or 1 for
rejection. Browser deployments need WebAssembly and Web Crypto; the existing
backend constructs its RNG-bearing configuration even on the verification path.

[SOURCE] The fixture runner calls the same JS/WASM API, first on the genuine
proof and then after changing one output digit in public row zero. It requires
the second call to reach the actual verifier and reject. It creates no proof.
Fixture hashes provide transport integrity; the committed application/fixture
is the trust anchor in this local example.

[SOURCE] A native CLI uses the identical wrapper core:

```sh
cargo build --release --locked --offline --bin vfhe-verify -j 2
target/release/vfhe-verify template.json public_rows.json proof.bin EXPECTED_TEMPLATE_SHA256
```

[SOURCE] Exit 0 means verified, 1 means rejected, 2 means CLI/I/O error. Its
stdout is the same verification JSON. Neither consumer reads a secret key.

## What this consumer establishes

[SOURCE] It checks a proof of the selected public coefficient relation. The
prover lane supplies a Lean-emitted template and rows extracted from actual
BFV ciphertexts. This wrapper does not itself decode BFV ciphertext blobs,
authenticate their origin, prove ciphertext-key membership, authorize a learner
event, check FIFO policy, or decrypt an answer. Those are separate application
bindings. It makes no new security or end-to-end learner correctness claim.

[SOURCE] Limits are 16 MiB template text, 16 MiB rows text, 64 MiB proof,
65,536 rows and width at most 256. Browser/Rust/WASM/library behavior remains
the execution TCB. Malformed-input or resource failure is never reported as a
successful proof; applications should discard a worker after a runtime trap.

[SOURCE/EXECUTED history] The original HidingFRI configuration rebuilt salted
public preprocessing differently between prover and verifier. Its first proof
failed natively and through WASM; `results/proof001-debug.json` and
`results/pre_adapter/` preserve that unsuccessful stage. The shared adapter
corrects only public preprocessing. Its explicitly named portable RNG avoids
`SmallRng`'s different native64/wasm32 algorithms. The unsuccessful proof is not
included in either public fixture, and no check or parameter was weakened to
obtain the successful results.
