# Exact learner score encoding and one-batch contract

[SOURCE] Input is the known-public BANKING77 prototype learner checkpoint at revision128, eight active examples per class, with its cached integer queries. Source hashes, class order and first-test-row-per-class selection are pinned in `input_reference.json`; `prepare_inputs.py` reads only the five explicitly authorized public reference files. The final bias coordinate is verified zero and omitted. No encoder is rerun. This is reused-data integration, not a new utility estimate. The existing 320-row utility result is separate.

[DERIVED integer domain] Let `v[c,f]` be the sum prototype and `w[t,f]` the query. The reference is `S[t,c]=Σ_f w[t,f] v[c,f]` with 576 features. Bounds `|v|≤1016`, `|w|≤127` give `|S|≤B=74,322,432`. Actual selected coordinates are prototype −535..545 and query −69..80. All64 computed scores and eight alphabetical-tie argmax decisions match the cached exact reference before encryption. Active class counts are equal, so sum-score argmax is the existing classifier.

[DERIVED two residues] Choose coprime `p0=16381`, `p1=16369`; product268,140,589 exceeds `2B`. For each limb use `Δ_l=floor(q/p_l)`, `q=18446744069414584321`, and encode prototype coordinate `m_l=Δ_l*(v mod p_l)` in the field. CRT of the two returned score residues, centered in the product modulus, therefore uniquely recovers every permitted signed score. No modular value is substituted for an integer score.

[DERIVED packing] Use `D=4096`, integer width16384 and64 rows in query-major/class-minor order. Class c starts at `(c//3)*D+(c%3)*1152`. Its two576-coordinate residue vectors occupy offsets0 and576 within that1152-block. Each block lies entirely in one D-chunk. The query row has coefficient `w[t,f]` at the first limb's locations and zero elsewhere. Upstream `Matrix::process` maps a chunk `(a0,a1,...,aD−1)` to `A(X)=a0−Σ_{j=1}^{D−1} a_j X^(D−j)`. Hence coefficient u of `A*M mod(X^D+1)` is `Σ_j a_j M[j+u]` whenever every nonzero support j satisfies j+u<D. This holds here for u=0 and576. These two output coefficients are exactly the two limb dot products. Four input ciphertexts provide power-of-two padding; the fourth message chunk is zero. All other output coefficients are ordinary ring-product outputs; this construction imposes no restriction on what a holder of the full recipient key could decrypt.

[SOURCE/DERIVED encryption] Keep the existing rank-one binary-key RLWE family, uniform field mask, Gaussian `sigma=2^33`, and D4096. `encrypt_scaled` performs `b=a*s+mean+round(G)` with exact signed field addition. This replaces the original demonstration encoder's uniform power-of-two scale and `2^64` wrapping arithmetic; it does not alter the prover, verifier or PCS. Each coordinate may have a different plaintext scale because the encrypted object is simply a field polynomial. Error samples and secret key stay in process memory. No rejected sample is resampled; a failed run is final.

[DERIVED decoder condition] For one selected output coefficient and limb, set `T=Σ_f w_f*(v_f mod p)`, `E=Σ_f w_f e_f`, `r=q mod p`. The decrypted phase is `z=(ΔT+E) mod q`. Exact integer decoding is `round(p*z/q) mod p`, implemented with u128 arithmetic as `((p*z+floor(q/2))/q) mod p`. Since `pΔ=q−r`, correctness follows from `|pE−rT|<q/2`. A sufficient bound is `2*(p*E_bound+r*(p−1)*L1)<q`, where `L1=Σ|w_f|`. `input_reference.json` verifies this strict integer inequality for both moduli and every selected query.

[DERIVED conditional Gaussian bound] For independent ideal Gaussian samples before rounding, `Σ w_f G_f` has standard deviation `sigma*sqrt(Σw_f²)`. Rounding contributes at most L1/2. Taking `E_bound=16*sigma*ceil(sqrt(Σw_f²))+ceil(L1/2)` gives a sufficient event for all selected decodes. The 128-coefficient union bound is at most `256*exp(−128)≈6.585e−54`; independence between outputs is unnecessary. This probability statement is conditional on ideal Gaussian sampling. It is not a formal finite-precision analysis of rand_distr's floating-point sampler or an RLWE security estimate. Actual exact decryption must still be checked in the sole execution.

[EXECUTED public checks] Python verifies all input hashes, cached integer references, 128 shifted-coefficient identities, CRT coverage and16 strict decode bounds; all64 wrong-shift577 controls differ. A native public test uses the actual matrix lift to evaluate128 coefficients without encryption, checks their decoded residues, and checks centered CRT and signed decode fixtures including ±B and bounded error. Both checks pass; logs are retained. No crypto was run during these checks.
